ProposalQ uses application security controls and third-party infrastructure to support the protection of user accounts, professional information and application records.

This document describes the security-related features identified during our review of ProposalQ's implementation and highlights areas requiring further verification.

1. Application Security

ProposalQ is built using Django, a Python web framework that provides security-related functionality including authentication, session management and CSRF protection.

The effectiveness of these protections depends on correct configuration, deployment and ongoing maintenance.

2. HTTPS and Secure Connections

ProposalQ's reviewed production configuration includes HTTPS redirection and security settings for session and CSRF cookies.

These settings are intended to help protect browser communications when the application is correctly deployed.

The live deployment configuration must be verified before making broader security assurances.

3. Account and Session Protection

ProposalQ uses Django-based account and session functionality to support authenticated access.

Users should choose strong, unique passwords, protect their account credentials and avoid sharing access with unauthorised individuals.

4. Database and Information Storage

ProposalQ's reviewed architecture uses PostgreSQL database services provided through Neon.

Application records may include freelancer profiles, work experience, job descriptions, proposals, application outcomes and subscription information.

Database access controls, backup arrangements, retention periods and recovery procedures require operational verification.

5. AI Request Security

ProposalQ integrates with OpenAI to provide AI-assisted analysis and proposal generation.

The reviewed implementation includes input validation, request-size limits, processing timeouts and instructions designed to reduce the risk of malicious instructions embedded in user-supplied content.

These controls reduce certain risks but cannot eliminate every possible AI-related security issue.

6. Third-Party Infrastructure

ProposalQ's reviewed technical architecture includes:

  • Render for application hosting.
  • Neon PostgreSQL for database services.
  • OpenAI for AI-assisted processing.
  • Stripe for subscription billing integration.

These providers operate their own infrastructure and security processes.

ProposalQ must verify the applicable contractual, technical and data-protection arrangements before making specific assurances about them.

7. Operational Monitoring

ProposalQ records certain operational information associated with AI requests, including request status, timestamps, processing outcomes and usage-related metadata.

These records support application functionality and operational investigation.

The scope of production security monitoring, alerting and incident-response procedures requires further confirmation.

8. Security Incidents

No online service can guarantee complete protection against every security threat.

ProposalQ must establish documented procedures for investigating security incidents and assessing whether notifications are required under applicable data-protection law.

9. Responsible Security Reporting

A verified security contact and vulnerability-reporting process must be established before this document is published.

Security researchers should not attempt to access, alter or disclose other users' information without authorisation.

10. Security Review and Improvement

Security controls should be reviewed as ProposalQ develops, including changes to authentication, AI integrations, infrastructure, billing and database functionality.

No claim of independent certification, penetration-testing approval or formal security accreditation is made in this document.

11. Document Status

This document is a working draft based on ProposalQ's reviewed implementation.

Production infrastructure, access controls, backup and recovery arrangements, incident response and security reporting procedures must be verified before publication.
